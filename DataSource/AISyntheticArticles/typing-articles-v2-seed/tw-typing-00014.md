# 當軟體錯誤排查碰上不同部門說法不一致

【主旨：庫存系統無法完成日結】

客戶門市來信：

您好，昨晚門市執行日結時，畫面停在「資料傳送中」，等了很久仍沒有完成。我們重新登入後，前一天的交易還顯示未結。先前詢問貴公司客服，得到的回覆是網路不穩；今天業務又說可能是版本太舊。兩邊說法不同，麻煩先確認要從哪裡排查問題。

我們在南部鄉鎮，網路偶爾會斷。為避免資料重複，我們還沒有再按一次日結。

【軟體公司客服回信】

您好，謝謝您先停止重複操作。僅憑其他電腦可以上網，還不能排除系統連線中斷；但我們也尚未確認是網路造成，稍早若直接下結論，說明不夠完整，向您致歉。

請提供錯誤畫面的截圖、發生時間和程式版本。請遮蔽顧客姓名和交易內容，不需寄送完整資料庫。可以先記錄新交易，但暫時不要再次執行日結，也不要自行移除程式。

【客戶回信】

截圖與版本畫面已附上。錯誤畫面沒有代碼，只停在傳送中。想追問一下：客服電話說可以重開數據機，業務卻叫我們先更新。到底先做哪一項？如果更新到一半斷線，我們會更難處理。

您說可以記錄新交易，是指正常輸入，還是改用紙本？

【公司技術支援回信】

您好，我接手此案排查。更正兩點：目前沒有足夠資訊要求您更新程式；在確認前，也不建議直接重開網路設備。請維持現況，讓我們看日誌。

您可以正常輸入新交易，但先不要執行日結或補送昨晚資料。若畫面再次停住，請記下當時正在使用的功能。附件中的版本仍在我們可協助檢查的範圍，版本新舊目前不是首要判斷依據。

請再提供程式內「連線測試」的結果畫面。這項測試只確認該電腦與服務端的連線，不會改動交易資料。

【客戶回信】

已照指示測試，第一次顯示連線失敗，隔幾分鐘再測就成功。我們沒有重開設備。這是否表示網路就是原因？還是系統端也可能有問題？

【技術支援回信】

一次失敗、一次成功只能證明連線曾不穩，還不能確認中斷發生在哪一端。我們查到日結請求有送達，但回傳完成狀態沒有寫入門市端。接下來需要比對服務端紀錄與門市日誌，避免把同一批交易重送。

請勿刪除停住的那筆工作，也先不要手動改日期。我們會由後端同仁確認它是否已完成處理，再決定補寫狀態或重新傳送。

【客戶主管回信】

謝謝說明。不過我們從昨晚等到現在，內部結帳工作已經延後。麻煩不要再讓客服、業務和技術各說一種做法。請指定單一窗口，並告訴我們下一次回覆時間。若今天仍不能日結，也請提供暫時作業方式。

【公司專案窗口回信】

您好，後續由我統一彙整，技術判斷仍由支援工程師提供。業務不再另行指示更新。現在的共同結論是：門市可繼續輸入交易；暫停日結；保留原始錯誤與連線測試畫面；等待服務端與門市端紀錄比對。

今天下午會先回覆比對結果，寫明已確認項目和下一步。

【下午，技術支援更新】

您好，已確認服務端完整收到昨晚交易，沒有缺筆。問題出在完成訊息回傳時連線中斷，門市端因此保留未結狀態。後端已將該筆標記交由人工複核，請您先不要重新送出。

為確認畫面狀態，請登出程式後重新登入，不必重開數據機或電腦。登入後查看日結清單，若昨晚項目顯示完成，請截圖回覆；若仍顯示未結，也請直接告知，我們會繼續處理。

【客戶回信】

重新登入後已顯示完成，今日交易也都還在。截圖如附件。請確認今晚是否能正常日結，還需要先做連線測試嗎？

【公司專案窗口結案信】

您好，技術端已核對昨晚資料與門市畫面一致，今晚可依平常流程操作。執行前可先做一次連線測試；若測試失敗，先不要日結，回覆本郵件即可。此步驟是降低再次中斷的機會，不代表已將原因全部歸在門市網路。

本案紀錄如下：版本問題已排除，昨晚交易沒有遺失，也不需重新輸入；異常發生於完成狀態回傳期間。後續客服若接到同類狀況，會先保留資料並查閱紀錄，不再直接要求更新或重開設備。謝謝您逐項提供畫面，也抱歉前段說法不一致增加了困擾。
