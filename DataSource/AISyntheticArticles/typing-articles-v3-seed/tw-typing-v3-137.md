# 房客與住宿業者談住宿訂房內容與確認信不同

房客：我需要申訴並核對訂房。平台頁面選的是「山景雙人房」，確認信卻寫「山景標準雙人房」。兩個名稱只差兩字，但頁面條件不同。

業者：請提供平台訂單末四碼與入住月份，不必貼完整姓名或付款資料。

房客：末四碼 4827，下個月入住。原頁面顯示一大床、窗邊座位和可延後取消；確認信連結裡則是一大床、無指定座位，取消條件也不同。

業者：先查訂單快照，請稍候。

房客：可以等。不過請不要只回「房型依現場安排」。我在意的不是樓層，而是訂購條件被換成另一個房型。

業者：明白。平台後台目前顯示商品代碼為 RMT-2，但我們館內把 RMT-2 稱為「山景標準雙人房」。需要再比對您下單當時的平台頁面與確認信產生時間。

房客：所以只是名稱翻譯不同，還是真的不同？

業者：還不能只憑代碼回答。您提到窗邊座位和取消條件，這兩項確實須逐項核對。

房客：我有下單時的 App 截圖，可以上傳嗎？

業者：可以，請遮住姓名、QR Code 與付款末碼，只保留房型名稱、條件和截圖時間。

房客：已上傳三張。第一張是搜尋結果，第二張是結帳頁，第三張是電子郵件確認信。

業者：收到。結帳頁寫「山景雙人房」，但備註欄的代碼也是 RMT-2。取消說明與確認信確有一處日期表述不同，我們請平台客服調閱商品版本。

房客：住宿業者和平台會不會又互相叫我問另一邊？我已經在平台申訴頁，不想重開兩個案件。

業者：由我們在本串聯繫平台，不請您重新提交。房間本身可先保留，不會因查詢而取消訂單。

【一小時後】

房客：請問有進度嗎？

業者：平台回覆，您下單時「山景雙人房」是前台簡稱，對應館內的標準雙人房；一大床與基本山景條件相同。窗邊座位是照片呈現，不是保證配置。可是取消條件確實在頁面更新時套用錯誤版本。

房客：座位部分我接受不能指定，但取消條件不能事後變嚴。你們要採哪一份？

業者：採您結帳當時頁面所示條件。平台已在訂單 4827 加註，並重新寄出 PDF 確認信。房型名稱會同時寫「山景雙人房（館內名稱：山景標準雙人房）」。

房客：新信收到了。請再確認床型，不會到現場變兩小床？

業者：新 PDF 的床型欄為一大床，訂單備註也相同。若您主動要求更換才會另議，目前不會改成兩小床。

房客：早餐呢？舊信寫不含，新信也不含，這點一致。

業者：是，不含早餐。加購與否可於入住時詢問，但我們不在此預先保證當日內容或價格。

房客：好。原訂單保留、床型一大床、取消依下單頁面、窗邊座位不保證。四點都清楚了。

業者：訂單仍為 4827，沒有重新扣款，也沒有另建一筆。平台頁面的房型名稱已送修正，避免其他房客再把簡稱與館內名稱當成兩種完全不同的房。

房客：這樣可以結束申訴。我會保留新版 PDF 與案件訊息，入住時以該信核對。
