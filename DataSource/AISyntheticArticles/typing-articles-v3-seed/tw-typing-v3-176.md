# 共享文件裡的排查問題

【文件：報表匯出錯誤排查】

問題描述｜填寫人：雅婷

客戶資料頁偶爾無法匯出 PDF。錯誤畫面截圖顯示「建立檔案失敗」，但我依同一筆資料重新操作時又成功。問題不是每次發生，現階段不要直接標成已修好。

〔工程師阿哲批註〕

請補瀏覽器、登入角色、發生時間和操作順序。單看截圖只知道最後一個提示，看不到 API 是否逾時。

〔雅婷回覆〕

瀏覽器是 Chrome，角色為客服主管。先開客戶頁，改聯絡地址，按儲存後立刻匯出。上午那次失敗，下午再做卻成功。QA 用測試帳號走同樣步驟也成功。

【可確認事項】

一、失敗截圖來自正式環境，時間戳記與客服通報相符。

二、該筆資料最後確實產生 PDF，但檔案建立時間晚於截圖十三分鐘。

三、QA 帳號與客服主管帳號權限不同。先前所稱「相同步驟」，其實登入角色不相同。

〔QA 小岑批註〕

我重跑時沒有先改地址，只是開頁面後直接匯出。因此不是完整重現。我會補做「改地址、立即匯出」和「改地址、等一分鐘再匯出」兩組。

【待查假設】

假設甲：地址儲存尚在背景更新，匯出服務先讀到舊版本。責任人：阿哲查看 API log。

假設乙：客服主管可見的備註欄含特殊字元，PDF 元件無法解析。責任人：雅婷提供遮蔽後的文字範例。

假設丙：瀏覽器快取顯示舊提示，實際檔案已建立。責任人：小岑比對前端訊息與伺服器時間。

〔設計師家豪批註〕

截圖中的提示位置和目前版本不同，可能是舊分頁。不過不能只憑外觀判定，請雅婷回想當時有沒有開著很久。

〔雅婷〕

那個分頁從早上一直開著，午休前才操作。可是重新整理後仍曾失敗一次，所以舊分頁可能相關，但不是唯一條件。

【重現紀錄一｜QA 小岑】

測試帳號，改一般地址，立即匯出：成功。等待一分鐘再匯出：成功。連做十次未出現錯誤。卡點是測試資料沒有客服備註，也不能在正式資料上反覆修改。

【重現紀錄二｜工程師阿哲】

以遮蔽後副本加入全形斜線與換行，第一次匯出失敗，API log 顯示背景更新尚未完成；等待後成功。但移除特殊字元再測，立即匯出仍可能失敗，因此可排除字元是必要條件。

〔小岑批註〕

我用客服主管權限的測試角色重跑，也出現一次。失敗條件較接近「儲存後立即匯出」，不是特定瀏覽器。Safari 與 Chrome 都有機會發生。

【決定與修正】

阿哲調整匯出流程：地址儲存未完成時，匯出按鈕顯示「資料更新中」，待 API 回傳完成後才可按；若背景更新失敗，頁面直接顯示重試，不建立 PDF。家豪負責訊息文字，小岑以兩種角色和兩種瀏覽器執行回歸測試，雅婷核對實際客服操作。

【驗證結果】

新版在測試環境連續執行，已能阻止儲存中的匯出；等待完成後，PDF 地址與頁面一致。QA 另外模擬更新失敗，畫面會保留原資料並提示重試，不再出現「檔案失敗但稍後自行建立」的矛盾狀態。

【上線安排】

修正已排入晚間版本。上線後由雅婷用非敏感測試資料操作一次，阿哲查看 log，小岑核對成品。原截圖與實際重做不同，是因先前忽略登入角色、資料更新狀態和分頁時間；三項條件現已寫入紀錄。若錯誤再現，依同一欄位補資料，不另開內容不全的新文件。

〔雅婷最後批註〕

我已把客服操作提醒放到團隊頁面，遇到按鈕暫停時先等更新完成，不用連續點擊，也不請顧客重填地址。
