# 手機倉頡「未打完也能選字」計畫

狀態：規劃中，尚未實作。

## 範圍與設定

- 先開發 iOS、Android 手機虛擬鍵盤的倉頡；桌面、實體鍵盤、簡易與注音不在本次範圍。
- 新增獨立選項「未打完也能選字」，說明：「輸入字根時，提前顯示相同開頭的候選字，常用字優先。」
- 手機倉頡虛擬鍵盤的「即時候選」與「未打完也能選字」兩個選項都預設開啟；設定缺值時採開啟，使用者明確儲存的開關選擇須保留，不在重啟或升級時重設。
- 新選項開啟時接管虛擬鍵盤的候選顯示，不要求啟用既有「即時候選」，也不改寫原設定；關閉後恢復原本規則。
- 「即時候選」只列出與目前字碼完全相同的字；新功能列出字碼以目前輸入開頭的字，包含完整碼符合者。

## 候選行為

- 從第一碼顯示候選；繼續輸入縮小範圍，Backspace 刪碼後重新查詢，清空字碼時清除候選。
- 相同字去重，所有前綴候選統一依固定常用字排名排序；未排名的字置後，同順位沿原字表順序。
- 預覽只剩一字也不自動送出。沿用既有候選列、點選與翻頁介面；選字後銜接原關聯詞流程。
- 第一版前綴排序不混入個人學習；既有完整碼的選字紀錄與原排序設定保留。
- 實作前固定空白、Enter、滿五碼查詢、錯碼清除、標點與 `?／*` 的互動規則，確保繼續打碼不會誤送預覽首選；不將無完整碼符合誤認為無前綴候選。
- 切換選項或輸入模式時先依原流程處理目前組字，再套用新行為；不將預覽狀態帶到實體鍵盤。

## 實作步驟

1. 確認常用字排名的來源、授權與覆蓋率；既有 1,500 字排名可供原型評估，正式採用前仍須核對。兩平台共用版本固定的獨立排名資源，不修改正式 `KeyKey.db` 或好打注音模型。
2. 在 Swift、Java 的倉頡查詢介面新增前綴查找，使用既有字碼索引；先過濾不可顯示字與去重、排序，再分頁，避免先截斷結果而漏掉常用字。
3. 加入有上限的查詢快取，量測第一、二碼的大量候選延遲與記憶體，再決定是否需要額外前綴索引；快速連打時不得顯示過期結果。
4. 接入兩平台的倉頡設定與虛擬鍵盤入口，確認兩選項的虛擬鍵盤預設值、缺值處理、明確選擇的保存、重啟及實體／虛擬鍵盤切換；既有「即時候選」與錯碼清除的互斥須依有效模式處理，不覆寫保存的設定。
5. 新增共用案例及各平台引擎回歸，再分別完成 iOS extension、Android IME 的實際觸控輸入驗收；完成實作後才更新平台文件與更新紀錄。

## 驗收

- 選項關閉時，既有倉頡行為、候選順序及設定完全維持；桌面、實體鍵盤與其他輸入法不受影響。
- 新安裝或設定缺值時，虛擬鍵盤的兩選項都為開啟；明確關閉任一選項後，重啟及升級仍保存其選擇。關閉「未打完也能選字」時，依目前「即時候選」設定恢復完整碼候選規則。
- 開啟時，每筆候選符合目前前綴、無重複、常用字順序一致，包含補充平面漢字的處理。
- 覆蓋一至五碼、刪碼、無候選、點選、翻頁、確認送字、標點、萬用字元、關聯詞與既有選項組合。
- 實際鍵盤驗證快速連打、切換 App／輸入法、生命週期回呼與選項切換，無漏字、重複送字或舊候選。
- iOS 跑受影響的 Swift 引擎測試與 extension 驗收；Android 跑相關單元測試、lint／debug 建置與 IME 驗收。引擎測試不代替實際鍵盤驗收。
