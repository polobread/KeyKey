# Windows 桌面真實宿主與實體鍵盤驗收

Windows x64 已安裝的 KeyKey 1.5.0 四種輸入法，於 2026-11-01 完成記事本與 Word 的局部真實宿主冒煙驗收；使用者另以實體鍵盤在記事本輸入好打注音固定長句，最終畫面及已存檔文字均為完整 19 字，無漏字或重複字。

自動操作使用 Windows `SendInput` 按鍵事件，不以貼上中文字驗證輸入法。實體鍵盤輸入來源由使用者確認，與自動送鍵的結果分開記錄。本次不是完整發布或安裝驗收，也沒有重跑全部共用桌面案例。

本紀錄固定描述當時已安裝的 DLL 與詞庫，不隨目前來源或 DB 更新改寫結果。準備最終 1.5.0 發布時，仍須使用最終來源與安裝包重新核對相關宿主／安裝證據，見[六平台發布準備](CROSS_PLATFORM_V1_5_0_RELEASE.md)。

## 本次設定

沿用既有使用者 profile，沒有清除學習。設定讀回為標準注音、UTF-8 字集、10 音節組字區、`12345678` 選字鍵、候選目標在游標後方、空白開候選關閉、Esc 清除整句關閉、繁轉簡關閉；中文啟動，初始為半形。關聯詞保留 `McBopomofo`，中文忽略 Caps Lock 的既有選項為關閉；Caps Lock 案例依這個實際值驗證，測試後切回關閉狀態。

## 傳統注音、倉頡與簡易真實 App 結果

三法均在記事本的新分頁與 Word 的新空白文件，以 `SendInput` 逐鍵輸入，六組局部冒煙皆通過。沿用已安裝產品與既有使用者設定，未重建或修改產品碼。輸入法透過既有 `PrimaryInputMethod` 偏好依序選取並讀回；本輪沒有驗證工作列選單操作。結束後恢復原先的 `SmartMandarin`，loader 設定檔與測試前備份的 SHA-256 完全相同。

| 輸入法／實際設定 | 記事本與 Word 的已觀察結果 |
|---|---|
| 傳統注音：標準配置、UTF-8 字集 | `su3` 開啟九鍵候選，分別選取「你」「好」後保留「你好」；另輸入未完成 `su`，Backspace 由「ㄋㄧ」退回「ㄋ」，Escape 清除未完成讀音且不改已提交文字。記事本另驗證 Next／Prior 翻頁及返回首頁；Word 此輪未測傳統注音翻頁 |
| 倉頡：即時／前綴候選開啟、滿五碼送出關閉、錯碼清除關閉 | `a` 即時開候選選「日」，`ab` 選「明」；`hk` 前綴依畫面選「喬」，完整 `hkrbr` 滿五碼仍等待確認，Return 再送出「喬」。`a?` 選「昌」、`a*` 選「日」，結果為「日明喬喬昌日」。`zzzzz` 加空白無候選時保留五個字根，Backspace 退一碼、Escape 清除，其餘文字不變 |
| 簡易：即時候選關閉、滿二碼查詢開啟、錯碼清除開啟 | 單碼 `a` 不立即開候選，按空白查詢後選「日」；`ab` 滿二碼開候選並等待選取，兩個 App 均驗證 Next／Prior 翻頁後選「明」；`jj` 依畫面選「車」，結果為「日明車」。`zz` 滿碼查詢無候選後清除字根，已提交文字保留 |

倉頡 `hk` 的「喬」在本機兩個 App 均為第 4 項；簡易 `jj` 的「車」均為第 2 項。選取依實際候選文字判斷，不把本機順位當成跨平台固定規則。既有關聯詞來源保留 `McBopomofo`，送字後出現的關聯候選以 Escape 關閉，再進行下一組字碼。

兩個 App 最終畫面均為三行／段「你好」「日明喬喬昌日」「日明車」，Word 的 UI Automation 文字亦讀回相同內容。依使用者指示，這輪不保存記事本或 Word 文件，Word 另存新檔對話框已取消；結果依畫面、候選及文字讀回記錄，不宣稱完成存檔逐字核對或這三法的實體鍵盤驗收。

## 實體鍵盤結果

使用者確認已用真正鍵盤在專用空白記事本輸入固定長句。agent 未在這份文件輸入測試句；完成回報後讀取畫面，確認全文與狀態列的 19 字，再透過記事本「檔案 → 儲存」保存既有文字。最終檔案逐字等於固定句，沒有漏字、重複字或額外換行，SHA-256 為 `4bc38a960d8095f63c5cc9747ca2f9d69cbddfda7caec690fb12c7e2e7790697`。

實體鍵盤來源以使用者回報為依據，最終畫面與檔案由 agent 核對；手打過程的第 10／11 音節未獨立擷取，因此只記為實體鍵盤全文驗收通過。前述 10／11 音節的中途證據來自自動送鍵，不能互相代替。鍵盤型號與 USB／藍牙連接方式未另錄。

## 證據與範圍

本機證據集中於 `Installer/local-builds/windows-desktop-acceptance-f2d4899/`，屬測試產物，不提交：

- `acceptance-results.json`：各檢查結果、輸入來源與未涵蓋項目。
- `environment.json`、`binary-evidence.json`、`pe-comparison.json`：測試初始設定、模組及建置識別比較；`environment.json` 的輸入來源描述是手打前的初始快照，最終狀態以驗收結果為準。
- `observations.json` 與對應 PNG：組字、候選、分段及使用者手打完成畫面。
- `notepad-automated-input.txt`、`word-automated-input.docx`、`word-committed-text.json`：真實宿主保存的自動送鍵文字及 Word 逐字核對資料。
- `physical-keyboard-input.txt`、`physical-keyboard-result.json`：使用者手打全文與核對結果。

其餘三法的本機證據另存於 `Installer/local-builds/windows-other-methods-0b8b25a/`，亦為不提交的測試產物：`observations.json` 與對應 JPG 記錄各步組字、候選、取消與最終未存檔畫面；`preference-*.json` 記錄方法選取／恢復讀回，`original-loader.plist` 是恢復核對用的初始備份。

本次只涵蓋上述 Windows x64 四法局部情境。x86 宿主、Windows Search／AppContainer、高 DPI／多螢幕、安裝／升級、工作列方法選單、真實 App 的 100 輪穩定性、其餘三法的實體鍵盤與好打注音手打中途邊界仍須另行驗證；macOS IMK 與 Linux／FreeBSD 原生宿主結果也不由本次推定。
