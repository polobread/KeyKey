# iOS 虛擬鍵盤字級與外觀量測

## 實作規則

- 主字依實際「ㄖ」鍵的可用寬高與 UIFont 量測求值，不寫死裝置像素或字號上限。
- 特大使用完整鍵內範圍；標準保留英數提示所需空間；中、大為兩端之間相同乘數的級距。
- 同一版面中，注音、倉頡／簡易字根、英文、數字與全形標點使用共同主字級。
- 聲調保留原相對比例。鍵帽間隔只改可見鍵帽面積，不改共同字級與點擊範圍。
- 分離鍵盤左右空白共用相同字級；模式等多字功能標籤另按實際可用框縮放，不截成「…」。

## 驗證範圍

iPhone 16 Plus、iOS 27.2（24B119），於真正鍵盤 extension 的輸入宿主視窗量測。
`KeyKeyTypography` 為手動 test plan；只有明確加入 `KEYKEY_TYPOGRAPHY_MEASUREMENT` 編譯旗標才有批次入口。
它呼叫原設定 delegate 回呼，等待宿主排版，再讀取原生 UIView／UIFont。
一般 Debug／Release 不包含該入口或診斷標籤。

四種中文輸入法 × 三版面 × 三鍵帽間隔 × 四字級 × 兩刪除鍵位置 × 直橫式，共 **576 組**。
另加入英文、數字／符號兩個獨立平面，共 **288 組**；合計 **864 組**，每種方向 432 組。
iOS 沒有 Android 的「整合底部控制鍵」開關，此軸不適用。

批次檢查是無組字時的外觀切換；不代表 864 次完整的組字、候選與宿主送字交易。
另外透過真正設定 UI 切換並保存三版面、四字級、直橫式 **24 張實機截圖**。

## 量測結果

864 組內各方向的鍵區、視窗、底部位置皆保持一致；主字級差異、左右空白差異及模式標籤截斷均為 0。
同一版面與字級在四輸入法、英文／數字、三鍵帽間隔及兩刪除位置間使用相同主字級。
各版面的欄寬不同，字級隨可用空間換算；切換版面不改鍵盤總高度。

下列座標是 extension 的原生視窗／內容座標，單位 pt：

| 方向 | 視窗範圍 x/y/w/h | 主鍵區 x/y/w/h | 主鍵區底部 |
|---|---|---|---|
| 直式 | 0 / 0 / 430 / 330 | 3 / 55.6667 / 424 / 271.3333 | 327 |
| 橫式 | 0 / 0 / 698 / 155 | 3 / 32 / 692 / 120 | 152 |

| 直式 | 標準 | 16.5851 | 19.9915 | 24.0975 | 29.0469 |
| 直式 | 對齊 | 19.3178 | 23.2287 | 27.9312 | 33.5859 |

每一版面的四級字號為等比例遞增；跨方向的數值由各自可用鍵高與寬度決定。
三種模式標籤「ㄅ/英」「英/數」「數/ㄅ」在所有量測組合都完整落在標籤框內。
