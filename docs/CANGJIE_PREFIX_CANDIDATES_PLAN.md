# 倉頡「未打完也能選字」跨平台計畫

狀態：已提供 iOS／Android 虛擬及實體鍵盤試用；桌面接入待開發。

## 手機版已接入

- iOS extension 與 Android 觸控倉頡讀取虛擬組；iOS App 前景實體編輯器與 Android 實體候選列／浮動窗讀取實體組。兩組各有即時候選與前綴開關，虛擬缺值預設開啟，實體缺值預設關閉。macOS／Windows／Linux 未修改。
- 一至四碼即時查完整碼與前綴，五碼只查完整碼；前綴採 1,500 字排名、去重並過濾缺字／標點／符號後最多 36 字。Swift 與 Java 使用相同 Unicode NFC 文字識別，保留原始候選文字顯示。
- 預覽只剩一字也不自動送出；即使開啟「滿五碼查詢」，一般字根的第五碼仍只預覽。第六個字根沿既有流程確認目前候選再開始新碼。萬用字元查詢保留原確認規則。
- 空白沿既有「單頁選首字、多頁翻頁」；Enter 確認目前反白候選，點候選直接選字，刪碼重新查詢。標點與模式切換沿原本組字交接流程。
- App 倉頡設定分列虛擬／實體組；iOS 實體編輯器也可調整實體組。四個候選開關分開保存，保留舊版已儲存的即時候選值。iOS 舊設定只供遷移讀取，新共用非預覽選項與兩組候選值另存，避免 App Group 更新另一組時覆寫原選擇。
- 排名由 `tests/generate_cangjie_ranking.py` 從既有 TSV 產生兩平台程式資源；以 `--check` 核對來源 SHA-256 與內容，不改動正式 DB。

## 範圍與設定

- 適用倉頡：iOS、Android 手機版，以及 macOS、Windows TSF、Linux／FreeBSD Fcitx 5 桌面版。簡易、注音與歷史 Windows IMM32 不在本次範圍。
- 手機版涵蓋虛擬鍵盤與 USB／藍牙實體鍵盤，兩種輸入來源各自保存「即時候選」與「未打完也能選字」，共四個分開保存的候選值；虛擬組預設開啟、實體組預設關閉，兩組互不連動。同組的前綴開關依賴即時候選，錯碼清除亦各自保存。iOS extension 不接收一般外接鍵盤事件，iOS 實體鍵盤驗收在容器 App 前景的編輯器進行。
- 新增從屬選項「未打完也能選字」，說明：「輸入字根時，提前顯示相同開頭的候選字，常用字優先。」

| 產品 | 「即時候選」預設 | 「未打完也能選字」預設 |
|---|---|---|
| 手機版：iOS／Android 虛擬鍵盤 | 開啟 | 開啟 |
| 手機版：iOS／Android 實體鍵盤 | 關閉 | 關閉 |
| 桌面版：macOS／Windows／Linux／FreeBSD | 關閉 | 關閉 |

- 新安裝及設定鍵缺值時，才採該產品與輸入來源的預設值。使用者已明確儲存的任一開關選擇須保留，不在重啟、升級或更換鍵盤來源時重設；新選項缺值不代表可以覆寫既有「即時候選」值。
- 手機設定介面清楚分列虛擬／實體鍵盤的兩個開關，儲存鍵與讀取入口分離，不用單一共用值互相覆寫。升級時，新的來源專屬值優先；若尚無專屬值但舊版已有明確共用「即時候選」設定，首次遷移將該選擇分別保留到兩組，之後各自保存；完全缺值才採該輸入來源的預設值（虛擬開啟、實體關閉）。新功能缺值亦依各組預設值處理。
- 「即時候選」只列出與目前字碼完全相同的字；「未打完也能選字」在一至四碼追加嚴格前綴候選，五碼只列完整碼候選。
- 「未打完也能選字」只有在同組「即時候選」開啟時才能操作及生效。即時候選關閉時，前綴選項變灰、不查前綴，保留勾選以便重新開啟時恢復。

| 即時候選 | 未打完也能選字 | 輸入字根時的行為 |
|---|---|---|
| 關閉 | 關閉 | 沿用原本確認後查詢的流程 |
| 開啟 | 關閉 | 預覽完整碼候選 |
| 關閉 | 已勾選但停用 | 沿用確認後查詢，不追加前綴 |
| 開啟 | 開啟 | 預覽完整碼與前綴候選 |

## 候選行為

### 一至五碼規則

用途是讓使用者提前選字，也保留少量翻頁空間，方便後續字根拿不準時找字。前綴候選上限為 36 字；手機目前每頁 9 字，相當於四頁的量。桌面沿用各平台候選窗與分頁設定，不因本功能強制改成每頁 9 字。完整碼候選另計，合併後總頁數可能超過四頁。

下表的 A、B、C、D、E 代表依序輸入的字根，不是特定字母。嚴格前綴指「完整符合目前全部字根，而且還有至少一碼」，總長最多五碼。

| 已輸入 | 第一組：完整碼，沿用原排序 | 第二組：嚴格前綴，依常用度排序 |
|---|---|---|
| A（一碼） | 完全符合 A | A 開頭的二至五碼候選，合計最多 36 個不同候選字 |
| AB（二碼） | 完全符合 AB | AB 開頭的三、四、五碼候選，合計最多 36 個不同候選字 |
| ABC（三碼） | 完全符合 ABC | ABC 開頭的四、五碼候選，合計最多 36 個不同候選字 |
| ABCD（四碼） | 完全符合 ABCD | ABCD 開頭的五碼候選，最多 36 個不同候選字 |
| ABCDE（五碼） | 完全符合 ABCDE | 不查詢 |

- `ABXXX／ABCXX／ABCDX` 表示剩餘可有的字根，不限於剛好補足五碼。例如 AB 的補充候選包含 ABX、ABXX、ABXXX。
- 第一組完整碼候選一律在前，沿用各平台既有字表、標點覆寫、字集限制與選字紀錄排序設定；不套用新常用字排名，也不受第二組 36 字上限影響。
- 第二組採用既有 1,500 字排名：以候選文字對照排名，排名數字小者優先；未收錄的字置後，同順位及未收錄字沿原字表列序排列。不混入個人學習，不按剩餘碼長分組。這套排名適用一至四碼的全部嚴格前綴候選，且不能讓前綴組超前完整碼組。
- 先依平台既有字集與顯示支援規則過濾、按候選文字去重，排除已在第一組出現的字，再排序及取第二組前 36 字；最後接在第一組後面，沿用候選列或候選窗及分頁。這個上限是整組上限，不是每頁或每種碼長各 36 字。
- 同字有多組碼時，只要其中一組完整符合目前字碼就歸入第一組；在第二組重複符合時以最早符合的字表列作同順位依據。完整碼組去重保留原排序中第一次出現的位置。
- 完整碼沒有結果、但嚴格前綴仍有結果時，照常顯示第二組，不可因此觸發錯碼清除。一至四碼即使沒有完整碼也要查詢前綴；五碼沒有完整碼時不放寬成較短前綴。
- 超過第二組前 36 名的字仍可繼續打碼找出。每次增碼或 Backspace 都依完整資料重新查詢，不得只從上一輪保留的 36 字篩選；清空字碼時清除候選。
- 前綴仍嚴格符合全部已輸入字根，不新增模糊比對或錯根容錯；若已輸入的字根有誤，須退格修正。

### 選字與既有操作

- 預覽只剩一字也不自動送出；一至四碼繼續輸入字根時更新候選，不因有預覽首選而提前送字。選字後銜接各平台原有的後續流程；已有關聯詞的入口保留關聯詞行為。
- 完整碼的選字紀錄與原排序設定保留。前綴選字不寫成目前短碼的完整碼偏好；第一版不新增前綴個人學習，避免影響日後同短碼的完整碼排序。
- 上表限定一般字根查詢；`?／*` 沿用既有萬用字元查詢，不再自動追加前綴，亦不以本功能的 36 字上限截斷。標點與字表屬性列不混入嚴格前綴字組。
- 實作前固定各平台空白、Enter、滿五碼查詢、第六個字根、錯碼清除與標點的互動規則，區分預覽及已確認候選。手機既有「空白單頁選首字、多頁翻頁」、桌面原有空白／Enter／選字鍵／Page Up／Page Down 與候選窗導覽需分別核對，不能直接以結果筆數決定送字。
- 切換選項、輸入模式或觸控／實體輸入來源時，先依原流程處理目前組字，再採用新行為；舊候選與延遲回覆不可覆蓋新狀態。
- 「即時候選」與「錯碼清除」維持互斥：開啟即時候選會關閉錯碼清除，開啟錯碼清除會關閉即時候選並停用前綴選項。手機虛擬／實體的錯碼清除分開保存；舊版兩項同時開啟的衝突值，讀取時以既有即時候選選擇優先，將錯碼清除視為關閉。

## 平台接入

| 平台 | 查詢與設定入口 | 本次接入 |
|---|---|---|
| iOS | Swift `TableCandidateStore`／`BopomofoEngine`，App 與 extension 設定 | 虛擬鍵盤及 App 前景實體鍵盤，各自保存兩個開關，共用排名 |
| Android | Java `TableCandidateStore`／`BopomofoEngine`，App／IME 設定 | 虛擬與實體鍵盤各自保存兩個開關，共用排名；實體候選列及浮動窗讀取實體組 |
| macOS | 共用 `OVIMGeneric`、IMK 與 macOS 設定介面 | 加入前綴預覽與設定，兩項缺值均關閉 |
| Windows | 共用 `OVIMGeneric`、TSF 與目前設定介面 | 加入前綴預覽與設定，兩項缺值均關閉 |
| Linux／FreeBSD | `CinDictionary`／`Engine`、Fcitx 5 adapter 與設定 | 補齊兩個候選選項及前綴預覽，兩項缺值均關閉 |

- macOS、Windows、iOS、Android 的倉頡使用 `KeyKey.db` 內的 `Generic-cj-cin` 表；Linux／FreeBSD 倉頡讀取 `cj-ext.cin`。共用排名不代表可假設所有入口候選集合與列序完全一致。
- SQLite 入口以原 rowid 作字表列序；CIN 入口須保留原來源列序，不能拿 unordered map 的迭代順序作排序依據。
- 完整碼與未收錄排名的字保留各自來源順序。對相同候選集合，1,500 字的相對排名須跨平台一致；字集限制、字型支援與既有個人學習造成的差異另列診斷。

## 查詢與效能界線

- 一至四碼同時查完整碼與嚴格前綴；五碼只做完整碼查詢。SQLite 使用既有字碼索引；CIN 入口採適合其資料結構的前綴查找。兩者都限定合法字根與字碼長度，避免將 metadata 當候選。
- 一碼前綴範圍較大，須使用索引或有序查找與有上限的結果保留方式，量測各平台延遲及記憶體，避免一次把數千字交給介面。
- 36 字限制顯示及快取結果量，不代表查詢只需讀 36 列。必須檢視所有符合範圍的候選，或採能保證同樣前 36 名的查詢方案；不可先按原字表取前 36 字，再套常用度排序。
- 正式 DB 倉頡表已有 key 索引；本機 SQLite 的 `ab*` 查詢計畫可使用索引範圍。這不代替其他入口的效能驗收。
- 快取必須有上限；查詢內容、字集限制、標點模式、排名版本及影響顯示的條件不同時不得誤用舊結果。完整碼個人排序須反映最新紀錄，快速連打不得顯示過期結果。
- 排名固定採 `DataSource/AISyntheticBigram/common-single-character-pronunciations-1500.tsv` 的「排名／單字」欄，不使用讀音作倉頡排序。只涵蓋這 1,500 字；未收錄字依字表順序補足候選，仍受整組 36 字上限限制。此排名不保證重現截圖輸入法的順序。
- 排名資源載入後以記憶體對照表取得排名，不在每次按鍵時另查一份資料庫排名表。不修改正式 `KeyKey.db`、原始 CIN 字表或好打注音模型。

## 實作步驟

1. 從既有 1,500 字 TSV 提取單字與排名，整理五個 frontend 共用、版本固定的獨立排名資源，保留來源與授權記錄；驗證 1,500 個不同單字、排名完整且無重複，確認各平台打包路徑。
2. 在 Swift、Java、共用 `OVIMGeneric` 與 Linux CIN 引擎加入一至四碼嚴格前綴查找，保留符合字碼、原字表列序及完整碼／前綴來源，以供分組、去重與學習判斷。完整碼沿原排序，第二組才按排名截取 36 字，合併後不得再次整體套用個人排序。
3. 接入各平台的兩項設定、缺值預設與保存流程。手機虛擬及實體鍵盤分成兩組獨立開關，虛擬組兩項預設開啟、實體組兩項預設關閉，桌面兩項亦預設關閉；既有明確設定不重設，來源切換只套用目標組設定。Linux／FreeBSD 一併補上即時完整碼候選的設定與行為。
4. 固定各入口的確認與送字互動，量測一至四碼及五碼查詢的延遲與記憶體，特別覆蓋一、二碼大量候選、快速連打及焦點切換。
5. 建立共用案例，各自完成引擎與 frontend 驗收。完成實作後才更新平台使用文件與更新紀錄，不因擴充計畫改動平台版號。

## 驗收

- 兩個選項關閉時，沿用該平台既有倉頡行為、候選順序及設定；簡易、注音與其他輸入法不受影響。
- 新安裝及缺值預設按產品表驗證：iOS／Android 虛擬組兩項開啟、實體組兩項關閉，macOS／Windows／Linux／FreeBSD 兩項關閉。明確開關任一選項後，重啟及升級仍保存選擇；新增設定鍵不覆寫舊鍵。
- 手機虛擬及實體鍵盤的四個開關分開驗證：修改任一組不影響另一組；連接 USB／藍牙鍵盤、改用觸控、重新連線或重啟時，讀取對應組且不改寫任一組的明確選擇。iOS 以 App 前景編輯器驗收，不能聲稱 extension 接收到一般外接鍵盤事件。
- 驗證舊共用設定遷移：明確關閉即時候選者的兩組均保留關閉，已存在的來源專屬值不覆寫；首次遷移後改一組不影響另一組。
- 各設定組覆蓋候選開關的四種儲存組合：即時候選關閉時，前綴即使已勾選也必須停用且不可查詢；另驗證錯碼清除／即時候選雙向互斥、前綴灰階與重新啟用後恢復勾選。
- 一碼包含二至五碼前綴、二碼包含三至五碼、三碼包含四至五碼、四碼包含五碼；五碼無前綴查詢。每字符合全部已輸入字根，增碼後不保留已不符合的字。
- 完整碼組優先，與同設定、同學習紀錄下的原順序一致（重複文字保留第一次出現）；不套用新排名，也不受 36 字上限截斷。
- 第二組可正常翻頁，過濾、去重並排除完整碼重複字後最多 36 字。涵蓋補充平面漢字、同字多碼、未收錄字、字集限制與缺字過濾。
- 一至四碼均驗證 1,500 字排名，較小排名在前、未收錄字依原列序置後、不同碼長混合排序；相同候選集合的已排名字順序跨平台一致。
- 建立超過 36 字的案例：原字表第 36 列之後的常用字仍能入選；上一輪未入選的字增碼後仍能出現，刪碼後重新取得正確前 36 名。
- 覆蓋沒有完整碼但有前綴、兩組皆空、預覽僅一字、合併跨頁、前綴選字不污染短碼學習，以及各入口原有的選字後流程。
- 覆蓋一至五碼、刪碼、點選、鍵盤選字／導覽、翻頁、空白／Enter、滿五碼查詢、第六碼、標點、萬用字元、設定互斥與模式切換；繼續打碼不誤送預覽首選。
- iOS：受影響 Swift 引擎案例、extension 觸控及 App 前景實體鍵盤驗收；Android：相關單元測試、lint／debug 建置及 IME 觸控／實體／浮動窗驗收。
- macOS：共用模組回歸、設定保存及 IMK 真實文字宿主；Windows：按 tsf／settings 分類建置受影響 target，使用對應 CTest 篩選並在 Windows 文字宿主驗收；沒有 bitness／ABI 變更時先驗證日常開發架構。
- Linux／FreeBSD：引擎與設定回歸、staged install、Fcitx 5 X11／GNOME Wayland 分層驗收；FreeBSD 的建置與實際桌面證據另列。引擎測試不代替各平台實際輸入驗收。
- 生命週期、快速連打、切換 App／焦點／輸入法及選項切換，均無漏字、重複送字或舊候選。
