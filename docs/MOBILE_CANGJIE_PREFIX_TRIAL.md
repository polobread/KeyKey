# 手機倉頡前綴候選試用

提供 iOS／Android 虛擬及實體鍵盤試用。桌面接入仍在[跨平台計畫](CANGJIE_PREFIX_CANDIDATES_PLAN.md)中，尚未開發。

## 試打方式

1. 切換倉頡，開啟「倉頡設定（虛擬鍵盤）」的「未打完也能選字」；新設定缺值預設開啟。先開啟「即時候選」，才能操作前綴選項；開啟即時候選會關閉錯碼清除。
2. 輸入「竹」：先看到完整碼候選，後面追加常用前綴字；「喬」尚未進入前 36 個前綴。
3. 再輸入「大」：第一頁即可點「喬」，不用再打剩餘三碼。實際順位會隨缺字過濾及既有完整碼學習而異。
4. 重新試「竹大口」及「竹大口月」：「喬」仍可選，後者只有「喬、䀉」（依系統字型支援過濾）。
5. 打完「竹大口月口」：只預覽「喬」，不因僅一字而自行送出。點選或 Enter 確認；空白維持單頁選首字、多頁翻頁。
6. 在前綴中刪碼、翻頁後繼續輸入，候選應重新查詢；不能保留已不符合的字。點選前綴後可直接開始下一個字。

完整碼維持原排序並一律在前，前綴才使用固定 1,500 字排名，未收錄字依字表列序補足。前綴去重、過濾缺字與標點／符號後最多 36 字；完整碼數量另計。要比較原行為，可關閉「未打完也能選字」，再依需要切換「即時候選」。

虛擬與實體各有「即時候選」及「未打完也能選字」，共四個分開保存的候選值；虛擬缺值預設開啟，實體缺值預設關閉，舊選擇保留。錯碼清除也分開保存；滿碼查詢、選字排序與標點維持共用。即時候選與錯碼清除互斥，前綴只有在即時候選開啟時才能操作及生效。

## 實體鍵盤試打

1. iOS App「輸入法設定」→「倉頡設定（實體鍵盤）」，或進入實體鍵盤編輯器的輸入法選單；Android App 設定的「倉頡設定（實體鍵盤）」。先開啟實體組「即時候選」，再開啟「未打完也能選字」。
2. 輸入 HK（竹大），依畫面候選編號按數字鍵選「喬」；字型過濾可能影響編號，以畫面為準。
3. 使用 Page Up／Page Down 翻頁，再增碼或退格，候選須回到符合目前字根的結果。打滿 HKRBR（竹大口月口）只預覽，按 Enter 或數字確認。
4. 開啟實體組「錯碼清除」，即時候選應關閉、前綴變灰並停止生效；重新開啟即時候選，錯碼清除關閉、前綴恢復原勾選。虛擬組設定應維持原選擇。

iOS 外接 USB／藍牙鍵盤僅由琦琦 App 前景實體編輯器接收；keyboard extension 無法在備忘錄等其他 App 接管一般外接鍵盤。Android 既有實體候選列與浮動候選窗皆可使用。

## 開發驗證

- 排名資源：`python3 tests/generate_cangjie_ranking.py --check`，確認 Swift／Java 同源、1,500 個不同字及固定內容。
- Swift：`swift test --filter 'CangjiePrefixTests|TableInputTests'`，11 個相關測試通過（含兩組互斥與四種候選儲存組合），涵蓋實際 DB、逐碼、退格、萬用字元、學習隔離與 App Group 設定。
- iOS Simulator 26.5：實際 UI 測試通過，涵蓋實體預設關閉、前綴從屬控制項停用／啟用、錯碼清除互斥、開啟後以數字選「喬」、關閉還原、extension 提前選「喬」，以及簡易與實體編輯器原流程；保留 HK 候選截圖於本機 xcresult。
- iOS Debug 實機 App 與 extension 簽署建置及實機安裝成功；實機觸控效果仍由使用者試用確認。
- Android：`lintDebug testDebugUnitTest assembleDebug assembleDebugAndroidTest` 通過；127 個 JVM 測試通過，API 33 模擬器的 5 個 SQLite／字型／設定裝置測試通過，含虛擬／實體控制項灰階及互斥切換。
- Android 實際觸控 IME：在 debug 文字宿主輸入 HK，第一頁點「喬」，宿主內容驗證為「喬」。實體候選列與浮動窗另以硬體鍵事件 HK、數字 2 驗證宿主輸出「喬」，虛擬組預覽關閉、實體組即時候選與前綴皆開啟時，可使用實體組前綴；使用 API 33 模擬器，實際 USB／藍牙裝置效果仍由使用者試用確認。
- iOS extension 與 Android APK 包內 DB 的 SHA-256 均為 `8fc3aead36cefd16a77c0a0d4319f7a305fb712b752db09396c8ac2bd4ebbfdb`，與未修改的正式 DB 一致。
- 完整 `swift test`：23 個 suite 的 174 個 Swift Testing 測試及 4 個 XCTest 全部通過。
- 好打注音的 3 個長句邊界測試，以同一模型直接組句的結果核對逐鍵輸入、擠字與交接後的文字，不再把「玩／完」等同音字順位當成邊界驗收條件；仍檢查「請假」整詞擠出、觸控九／十與實體十／十一音節界線、19 音節全文完整，以及交接後不可重複送出。本輪未修改注音引擎或正式 DB。
