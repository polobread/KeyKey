# Android Pixel 11 鍵盤版面與字級驗證

驗證環境：Pixel 11、Android 17、1080×2424px、420dpi、系統字體比例 1.0。核對日期為 2026-11-05。這是 Android frontend 的實機量測紀錄，不是其他裝置、核心演算法或商店發布驗收。

## 目前字級政策

- 虛擬鍵盤的注音、倉頡／簡易字根、英文大小寫、數字、兩套符號及全形標點使用同一主字級。
- 標準、中、大、特大依共同基準使用 100%、115%、130%、145%；可用空間不足時，整組基準一起縮小，仍保留四檔比例。
- 不因字形筆畫較少或空白鍵較寬而獨立放大。分離鍵盤左右空白文字維持相同大小。
- 聲調維持與注音的相對比例，不再按聲調自己的稀疏筆畫填滿鍵帽。標準字級的注音與英數提示在小高度一起縮放。
- 鍵帽間隔不改變字級、按鍵中心、點擊範圍或主鍵區高度。

## 證據層級與範圍

1. 實際附掛 IME：四種輸入法 × 三版面 × 三間隔 × 四字級 × 兩刪除位置 × 兩底部整合狀態 × 兩方向 × 九高度，共 10,368 組。修正底部容器後完成完整一輪；後續共用字級修改不涉及這條量測／布局路徑。
2. 最終字級實作：在 Pixel 11 的隔離原生 `BopomofoKeyboardView`／`KeyboardInputView` 重新量測全部 10,368 組，以裝置捕獲的直橫向可用寬度、限高、密度與導覽區量測。每組再繪製中文、英文小寫、英文大寫及兩套數字符號，共 51,840 個原生字型案例。這層使用 Android 原生字型與 View，不將它稱為 51,840 次真實宿主交易。
3. 正常 App 程序：結束 instrumentation 後，各字級重新啟動、實際點選 EditText、收起與重開，核對八張螢幕截圖的背景像素與 WindowManager 視窗位置。

最終隔離矩陣的主鍵區高度逐筆與實際附掛基準相同。全部原生案例主文字字級一致、兩側空白一致、邏輯按鍵範圍內無溢出；全部 12,960 組四檔比較維持固定比例。在相同方向／高度／字級下，切換輸入法、文字版面、版型、間隔、刪除位置或底部控制不改變共用主字級。

## 主鍵區實測高度

下表不含自家底部保留空間或系統導覽安全區，單位為 px。每個方向／比例下，各外觀與輸入法組合相同。

| 高度 | 直式 | 橫式 |
|---|---:|---:|
| 50% | 433 | 302 |
| 75% | 650 | 453 |
| 90% | 779 | 544 |
| 100% | 866 | 604 |
| 110% | 953 | 664 |
| 125% | 1083 | 755 |
| 150% | 1299 | 906 |
| 175% | 1516 | 925 |
| 200% | 1732 | 925 |

橫式 175% 與 200% 已達系統可用高度上限。整合底部控制時，主鍵區仍保留 925px，鍵盤 View 高度 988px；容器使用 1017px 的配置預算，將 View 對齊底部，修正原本底部約 29px 空帶。一般 100% 直式的整合開／關分別為 929／971px；橫式為 667／696px，差異來自底部保留政策。

正常程序四檔截圖中，第一個「ㄅ」的可見筆畫高度分別約 29、35、39、43px。字型 hinting 會使整數像素邊界略有差異；Paint 字級的精確比例為 1、1.15、1.30、1.45。八次開啟／重開的實際鍵盤背景與系統視窗皆為 Y=1495–2424。

## 鍵盤跑到上方的未解紀錄

使用者提供的截圖確實顯示鍵盤背景在 Y=0–929，下方大面積空白。後續即時保存的畫面、系統視窗資料及正常程序開啟／重開檢查均在底部，尚未取得穩定重現，**不能宣稱這個上移現象的根因已修復**。

大量字級量測已改用隔離 View，避免改動正在使用的鍵盤繪製狀態。強制停止 App 時 Android 可能切到 Gboard；宿主測試與交還手機前必須核對真正選取的輸入法，不能把其他鍵盤的結果判成 KeyKey 行為。後續重現應保存發生當時的視窗 frame、實際截圖、輸入來源、方向、設定與生命週期事件。

## 回歸入口

- `KeyboardRenderingInstrumentedTest`：同字級跨文字種類／版面、全形標點、雙空白、短列括號／Emoji、聲調比例、字體／間隔不改鍵框、候選與點擊接合。
- `KeyboardBottomSpaceInstrumentedTest`：限高容器底部對齊、父層回算、保留空間、真實宿主收起與重開。宿主需選取 KeyKey，旋轉後讀取真正 resumed 的 Activity。
- `KeyboardTypographyTest`：固定比例、四級嚴格遞增、共同限高不壓平字級、不依按鍵撐大。

本次相關 instrumentation 共 23 個案例通過；五組純 Java 聚焦測試共 25 個案例通過，Android lint 與 Debug／androidTest APK 建置通過。純 Java 測試不使用 JNI；目前本機 JBR 缺 JNI headers，聚焦測試以 `-x buildGuanyinmaHostJNI` 排除無關建置依賴，沒有將其算作 host JNI 驗證。

原始 JSONL、量測程式、截圖、APK／來源雜湊與執行紀錄保留在本次本機產物目錄，不納入版本控制。沒有修改模型、使用者詞庫、其他平台或正式版本資訊。
